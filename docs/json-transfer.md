# JSON 备份与接口节点

本版区分两类文件。账号 JSON 恢复豆包工作登录状态；节点 JSON 只保存客户端连接配置。二者分别在工作台和接口节点页导入，选错类型会提示，不会修改现有数据。

## 快速使用

1. 正常启动项目，打开本机面板 `http://127.0.0.1:43862`。
2. 工作台点击「添加账号」，用独立 Chrome / Edge 完成登录。每次使用新的临时资料目录；同一账号再次登录更新凭据，不增加重复账号。
3. 需要备份时，点击「备份账号」，或勾选账号后点击「导出所选」。确认敏感凭据提示后下载 JSON。
4. 在工作台点击「导入 JSON」，先查看名称、数量和重复情况，再确认导入。默认跳过重复账号；选择「更新」会替换重复账号的登录状态。
5. 接口节点页可以手工保存节点，或导入节点 JSON；「导出配置」默认导出当前网关地址和模型 ID，不含 API Key。

## 账号文件

- 格式标识：`schema: doubao-work-accounts/v1`，`version: 2`。同时接受带完整豆包工作快照的 Agent2API version: 2 账号导出。
- 每次 1–20 个账号，文件不超过 512 KB。账号数更多时请分批勾选导出。
- 文件包含完整登录凭据，属于敏感备份。不要上传公开仓库、粘贴到 Issue 或交给不可信的人。
- 本项目导出仅包含非桌面的豆包工作登录快照，不包含管理员密钥、模型 Key、自动签到计划或其他提供商。任意代理配置不随账号文件应用。
- 导入预览只返回账号名称、标识与重复情况，不把 Cookie 传回界面。预览保存于服务内存，十分钟失效；每次确认仅提交一次。导入结果待核对时先刷新列表，不自动重试。
- 重复依据账号 ID 或提供商身份标识判断，提交前会重新核对。文件内重复、其他提供商、桌面快照和与其他类型账号的标识冲突会停止导入。
- 登录快照通常有时效。JSON 文件并不延长上游会话寿命；失效后请重新用浏览器登录。

## 节点文件

项目使用独立格式 `doubao-work-nodes/v1`，不是 Clash、订阅链接或任意 CPA 鉴权文件的通用转换器。见 [可编辑示例](examples/nodes.json)。

| 字段 | 含义 |
| --- | --- |
| `schema` | `doubao-work-nodes/v1` |
| `version` | `1` |
| `nodes` | 1–50 个节点 |
| `name` | 1–64 字符的节点名称 |
| `baseUrl` | 无内嵌凭据、查询参数或 fragment 的 HTTPS 地址；本机回环地址可用 HTTP |
| `models` | 可选，最多 100 个准确模型 ID |
| `apiKey` | 可选，完整 Key，列表中仅显示掩码 |
| `id` | 由项目生成的可选节点标识，用于回导更新 |

同标识或同名同地址的节点会更新。文件没有 `apiKey` 字段时保留原有 Key；字段为空字符串表示清空保存的 Key。普通导出会省略此字段，包含 Key 的导出需要额外勾选和确认。配置文件在 Unix 上以 0600 权限、Windows 上以私有 ACL 原子写入状态目录。

节点页用于保存、复制和导出连接资料。导入节点不会更换本项目上游、合并第三方账号池、发起模型测试或向节点地址发送凭据。导出文件是否可被其他客户端直接接收，取决于该客户端的格式；也可以按文件内容手动填写地址、Key 和模型。

## 批量账号操作

工作台支持搜索、状态筛选、排序、勾选当前列表和导出所选。每次最多选择 20 个账号。批量启用/暂停转发、加入/移出自动签到均先显示数量和动作，确认后执行。批量加入签到不改变每日计划总开关。

批量转发修改逐个进行；遇到失败即停止，返回「已完成 / 待核对 / 未尝试」数量，不自动重放整批请求。没有批量签到按钮，避免将结果待确认的领取重复提交。

## 云端入口

云端添加账号可连接已配置的本机助手：本机独立浏览器完成登录后，将本次账号通过 HTTPS 同步至私有配置中的云端目标。网页不接收任意目标地址或管理员密码。具体部署与配置见 [云端说明](cloud/README.md)。

此轮更新仅在本地验证，服务器升级应单独进行。JSON 凭据备份建议另行加密保存；此版下载的是普通 JSON，不宣称提供备份加密。
