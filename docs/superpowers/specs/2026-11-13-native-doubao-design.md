# 豆包工作原生独立后端设计

状态：设计待审阅，尚未实现。日期：2026-11-13。

## 1. 已确认目标

- 完全移除 Agent2API 核心及提供商插件运行依赖，运行本项目时不启动旧 App、server 或插件进程。
- 专注豆包工作，保留现有蓝白 / 深色面板、多账号浏览器登录、签到、账号 JSON、节点 JSON、管理员自建 API Key。
- Windows / macOS / Linux 使用统一 Node.js 22+ 源码启动，保持轻量；Linux 无桌面环境通过账号 JSON 或桌面助手迁入。
- 当前需处理的是云端接口收到 `710022004`。此码是上游要求人工验证，应与额度耗尽、普通限速明确区分。
- 现有云端服务、旧账号目录和主分支暂不替换。完成验收、备份和明确部署步骤后再切换。

## 2. 结构与边界

```text
客户端 ── OpenAI 兼容 API ──┐
                            │
管理面板 ── 本机 / HTTPS ───┤  原生 Node 服务（单进程）
                            ├── 账号与 API Key 存储
                            ├── 路由、并发与验证状态机
                            ├── 北京时间签到调度
                            └── 豆包专用协议适配 ── 官方网页服务
独立浏览器登录 ── 临时会话 ─┘
```

保留模型 API 43861 与管理面板 43862 两个默认回环端口，由同一个 Node 进程提供，尽量保持现有客户端地址与反代规则。管理入口继续执行 Host、Origin、自定义请求头与云端专用代理凭据检查；模型 Key 只访问模型接口。

服务内部使用清晰的 `AccountStore`、`KeyStore`、`DoubaoClient`、`Scheduler` 和 `RequestRouter` 接口。面板直接调用本项目服务接口，不再通过伪造的插件状态或另一个网关的管理 API 拼接功能。

现有跨平台路径、Windows ACL、临时浏览器隔离等模块可以复用；旧启动器中寻找、下载、安装和启动 Agent2API / 插件的部分从新版本运行链路移除。CI 同样移除上游核心下载与安装任务。

## 3. 账号、密钥与迁移

- 私有状态目录沿用运行目录配置，新的原生存储与旧文件分开，旧目录保留作回滚。
- 本项目持有账号身份、备注、启用状态、签到选择、验证状态和诊断记录。身份由官方会话核验结果确定，不信任文件里的名称来替代身份核验。
- Cookie 与其他登录资料以 AES-256-GCM 加密保存；随机主密钥与数据文件分开保存。Unix 使用 0700 / 0600，Windows 使用私有 ACL。此保护不宣称抵抗当前用户或系统管理员权限已失陷的场景。
- API Key 支持随机或自定义、命名、复制、启停；认证索引与受保护的可复制内容分开，模型 Key 与管理权限分离。
- 接受现有完整账号 JSON 作为迁移输入，将必要登录资料转换为本项目格式，丢弃任意代理配置和其他提供商内容。导入前预览、重复跳过 / 更新、一次性提交保持不变。
- 迁移使用已有导出或只读迁移工具，不为迁移启动旧 App；原始数据不删除。先核对账号数、身份、备注与开关，再单独验收调用。
- 账号导出仍是显式确认后的普通敏感 JSON；下载备份与本机加密存储是不同功能。节点 JSON 沿用独立格式，默认不含 Key。

## 4. 官方会话与协议确认

先通过官方网页、公开前端资源及账号持有人自己的受控会话，确认身份、模型目录、额度、签到和聊天请求的真实接口、字段及响应。实现自己的协议客户端，不复制或调用旧插件二进制。此步骤只记录必要协议事实，不把 Cookie、验证码、完整请求或个人资料写进仓库。

浏览器仍使用每账号新的私有临时目录，不读取日常浏览器资料，不开放调试监听端口。网页登录与滑块由账号持有人完成。验证模式下，窗口保留到持有人明确确认，避免刚检测到 session 就提前关闭窗口。

适配器必须区分：会话失效、人工验证、普通限流、额度不足、协议变化和网络故障。尚未打通或尚未验收的能力明确显示其状态，不伪造额度、签到成功、模型支持或聊天结果。

## 5. 人工验证状态机

账号状态至少包含：`ready`、`needs_login`、`needs_verification`、`rate_limited`、`disabled`。

收到 `710022004` 后：

1. 将**本次实际使用的账号**持久化为 `needs_verification`，记录发生时间、错误码及内部请求标识。
2. 结束本次请求，不对同一账号换模型重试，不把这个失败请求自动接力到其他账号。
3. 后续选路跳过该账号。其他未受影响账号可处理之后的新请求；若无可用账号，直接返回清楚的状态，不再联系上游。
4. 管理面板显示“需官网验证”和暂停原因，不显示“额度不足”。记录不保存消息正文、Cookie 或完整 Key。
5. 引导持有人在对应账号的豆包网页端发送一条普通消息，并亲自完成出现的人机验证。
6. 持有人明确确认后手动恢复；只进行一次由用户发起的受控复测。身份接口成功或定时刷新不自动清除聊天验证状态。
7. 若云端出口下仍返回同码，再次保持暂停并提示真实状态，不承诺等待固定时间必然恢复。

OpenAI 兼容错误保留上游码，并使用 `account_verification_required` 类型。模型客户端只得到请求标识，不泄露账号身份；管理员可在面板按该标识定位账号。已经输出 SSE 时，发送错误事件并终止流，不补正常成功完成标记。

普通限流单独遵循上游可用的重试时间；会话失效要求重新登录；额度不足只在有对应证据时标记。自动换出口和验证码代解不进入本项目运行流程。

## 6. 转发与调度

- 实现 `GET /v1/models` 和 `POST /v1/chat/completions`，优先打通一个真实文本模型的流式请求。
- 校验请求体大小、模型 ID、消息结构和 Key 状态。每账号默认单并发，账号选择与失败状态由本项目掌握。
- UTF-8 和 SSE 增量解析覆盖分片、截断、上游错误及客户端断开。客户端断开时取消相应上游请求。
- 明确完成事件才产生正常流结束；连接截断、协议错误和人工验证不视为成功。
- 签到保留北京时间、每天每账号自动尝试一次、提交前落盘、结果待确认不重复提交。`needs_verification` / `needs_login` 账号跳过调度。
- 功能与模型逐项验收；工具调用、图像及未确认能力保持明确的未验收标记。

## 7. 实施顺序

1. 只读协议核验与独立适配器契约；保留最小脱敏样本和明确字段说明。
2. 原生加密存储、Key、JSON 迁移及账号状态机，使用公开接口测试，先证明旧核心完全退出运行链路。
3. 接入官方身份与模型目录；打通独立浏览器登录，完成受控账号迁移。
4. 实现一个真实文本模型的流式转发及 `710022004` 暂停 / 手动恢复流程。
5. 接入真实额度与签到，补齐面板状态、错误、日志及跨平台启动文档。
6. 三系统自动测试通过后推送默认分支；真实账号及云端切换分别验收，服务器部署另行确认。

每一步先验证对应接口再扩大功能；不把本地模拟通过写成真实账号或云端调用通过。

## 8. 验收标准

- 新运行入口在无 Agent2API / 插件文件的目录中启动，进程及依赖检查确认只有本项目 Node 服务和用户主动打开的临时浏览器。
- 模型 API、管理 API、Key 权限及 JSON 往返在三系统测试通过；拒绝错误来源、错类文件、重复提交及越权访问。
- 原有账号数、身份、备注和开关迁移可核对；新账号真实登录由持有人在官网完成。
- `710022004` 测试证明首次错误后保存暂停状态、后续请求不触达该账号、重启后仍暂停；人工确认恢复后最多一次复测，再次失败重新暂停。
- 正常 SSE、错误 SSE、截断和断开均有测试。至少一个模型完成一次真实流式验收，费用与调用由持有人确认。
